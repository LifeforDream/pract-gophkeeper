# Сервер

```
bin/server [флаги]
```

При запуске сервер первым делом печатает версию и дату сборки, затем разбирает конфигурацию.

## Флаги и переменные окружения

| Флаг | Переменная окружения | По умолчанию | Значение |
|---|---|---|---|
| `-a` | `ADDRESS` | `localhost:50001` | Адрес и порт gRPC-сервера |
| `-l` | `LOG_LEVEL` | `info` | Уровень логирования |
| `-d` | `DATABASE_DSN` | *(пусто)* | Строка подключения к PostgreSQL. Пусто — данные хранятся в памяти |
| `-skip-migrate` | `SKIP_MIGRATIONS` | `false` | Не применять миграции при старте |
| `-tls-cert` | `TLS_CERT` | *(пусто)* | Путь к PEM-файлу сертификата сервера |
| `-tls-key` | `TLS_KEY` | *(пусто)* | Путь к PEM-файлу приватного ключа сервера |
| `-s` | `JWT_SECRET` | *(пусто)* | Секрет для подписи JWT (HS256) |
| `-t` | `JWT_TTL` | `1440` | Срок жизни токена в **минутах** (1440 = 24 часа) |
| `-f` | `FAKE_SALT` | *(пусто)* | Секрет для «фейковой соли» неизвестных логинов |

Флаги в стиле Go принимают один или два дефиса (`-a` и `--a`).

**Приоритет:** значение по умолчанию < флаг < переменная окружения. Если заданы и флаг, и переменная,
**побеждает переменная окружения**.

Булев флаг `-skip-migrate` включается самим наличием; для переменной окружения подойдёт `SKIP_MIGRATIONS=true`.

## Как выбираются хранилище и транспорт

Отдельных флагов «режим» нет, всё выводится из заданных значений.

### Хранилище

- `-d` не задан — **память**. Данные живут до остановки процесса.
- `-d` задан — **PostgreSQL**. При старте применяются миграции (они встроены в бинарник), если не указан
  `-skip-migrate`.

Строку подключения передавайте через `DATABASE_DSN`, а не флагом: аргументы командной строки видны другим
пользователям в списке процессов и попадают в историю оболочки.

### Транспорт

- `-tls-cert` и `-tls-key` заданы оба — **TLS** (только TLS 1.3).
- Не задан ни один — соединение **без шифрования**, в лог пишется предупреждение.
- Задан только один — **ошибка запуска**. Молчаливого перехода на соединение без шифрования нет.

Как получить сертификат и ключ — в [certificates.md](certificates.md).

### Секреты `-s` и `-f`

| Хранилище | Если не заданы |
|---|---|
| Память | Генерируются случайно при каждом старте |
| PostgreSQL | **Ошибка запуска**: оба обязательны |

Для PostgreSQL значения должны быть стабильными между перезапусками:

- `-s` (`JWT_SECRET`): при смене все выданные токены перестают действовать, пользователям придётся выполнить
  `login` заново.
- `-f` (`FAKE_SALT`): при смене меняется «фейковая соль» для несуществующих логинов, и по её нестабильности
  можно отличить существующий аккаунт от несуществующего. Не меняйте её без необходимости.

Генерируйте длинные случайные строки, например `openssl rand -base64 48`, и передавайте через окружение.

## Запуск с PostgreSQL

Для разработки в репозитории есть `docker-compose.yml` (PostgreSQL 18, пользователь `postgres`, пароль
`password`, порт 5432; пароль учебный):

```sh
docker compose up -d db

export DATABASE_DSN='postgres://postgres:password@localhost:5432/postgres?sslmode=disable'
export JWT_SECRET="$(openssl rand -base64 48)"
export FAKE_SALT="$(openssl rand -base64 48)"

bin/server --tls-cert certs/server.pem --tls-key certs/server.key
```

Сохраните `JWT_SECRET` и `FAKE_SALT`: при повторном запуске нужно подставить те же значения.

## Остановка

`SIGINT` (Ctrl+C) или `SIGTERM`: сервер перестаёт принимать новые запросы и дожидается текущих до 15 секунд,
затем принудительно закрывает соединения и освобождает хранилище. Таймаут не настраивается.

## Проверка работоспособности

Сервер регистрирует стандартный gRPC health-сервис (`grpc.health.v1.Health`), его можно опрашивать, например,
через `grpc_health_probe`.

## Ограничения

- Размер заголовка секрета — до 4 КиБ, содержимого — до 1 МиБ (в зашифрованном виде).
- Ограничения частоты запросов на вход нет. Не выставляйте сервер в публичную сеть без внешней защиты
  (обратный прокси, сетевые правила).
- Отзыва токенов на сервере нет: токен действует до истечения срока.
