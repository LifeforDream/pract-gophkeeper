# `get`

Показывает один секрет.

```
gophkeeper [глобальные опции] get [--offline] [--show] [--out <файл> [--force]] <id|name>
```

Опции должны идти **перед** `<id|name>`: парсер флагов Go останавливается на первом аргументе, не
являющемся флагом, поэтому `get github --show` отклоняется с ошибкой `invalid reference`.

## Опции

| Флаг | По умолчанию | Значение |
|---|---|---|
| `--offline` | выкл. | Не обращаться к серверу, читать только кэш |
| `--show` | выкл. | Печатать чувствительные поля открытым текстом |
| `--out <файл>` | *(нет)* | Только для `binary`: записать содержимое в этот файл |
| `--force` | выкл. | Вместе с `--out`: перезаписать файл, если он существует |

## Откуда берутся данные

Команда синхронизирует кэш (`ListChanges` с последней известной ревизии) и ищет секрет по id или имени среди
закэшированных заголовков. Тело секрета скачивается с сервера, только если в кэше нет тела нужной версии;
после скачивания оно сохраняется в кэше в зашифрованном виде и в следующий раз берётся оттуда. Расшифровка
всегда выполняется на клиенте, расшифрованное содержимое на диск не пишется.

Если сервер недоступен (`UNAVAILABLE` или таймаут) или указан `--offline`, всё читается из кэша, а в stderr
печатается предупреждение (`warning: server is unreachable, showing cached data` или
`warning: offline mode, showing cached data`); код выхода 0. Если нужного тела в кэше нет, команда завершается
ошибкой `body is not cached, retry when the server is reachable`. Поэтому без сервера доступны только те
секреты, которые вы уже открывали или создавали на этом компьютере. `--offline` не проверяет срок токена, но
требует сессию. Прочие ошибки (истёкший токен, TLS) кэшем не маскируются.

## Вывод

Первые две строки одинаковы для всех типов:

```
Secret id: <uuid>, name: <name>, type: <type>, version: <n>
Secret meta: "k=v k2=v2"
```

далее, по типам:

| Тип | Строки | Маскирование без `--show` |
|---|---|---|
| `login` | `Login:`, `Password:` | пароль выводится как `********` |
| `text` | `Text:` | нет |
| `binary` | `File name:`, `File size:` (в байтах) — или, с `--out`, `Wrote secret to file: <путь>` | нет |
| `card` | `Card Number:`, `Card Holder:`, `Card Expiry:`, `Card CVV:` | номер как `1234****5678` (только `*`, если короче 16 цифр), CVV как `***` |

## Бинарные секреты

Без `--out` печатаются только имя и размер файла, ничего не записывается. С `--out`:

- файл создаётся с правами `0600`;
- если он уже существует, команда завершается ошибкой `file already exists`, кроме случая с `--force`:
  тогда файл усекается и перезаписывается.

`--show` на бинарные секреты не влияет.

## Примеры

```sh
gophkeeper get github
gophkeeper get --show github
gophkeeper get --show 6f1c0b1e-0000-0000-0000-000000000000
gophkeeper get --out id_ed25519 --force ssh-key
```

## Ошибки

- `record not found` (код 1).
- `id or name X returned multiple values: [...]` — используйте id (код 1).
- `invalid reference` — позиционных аргументов не ровно один (код 2).
- `file already exists` (код 2).
- `body is not cached, retry when the server is reachable` — нужного тела нет в кэше, а сервер недоступен или указан `--offline` (код 1).
- `server is unavailable` — сервер недоступен (код 1); возможен, если кэш не удалось использовать.
