# GophKeeper CLI

`gophkeeper` — консольный клиент менеджера паролей GophKeeper. Он хранит на сервере логины, текст, бинарные
файлы и банковские карты; всё шифруется на вашем компьютере до отправки, поэтому сервер никогда не видит
ваши данные.

> **Восстановления пароля нет.** Ключ шифрования выводится из вашего пароля. Если вы его забудете, сохранённые
> секреты не сможет расшифровать никто. Смена пароля пока не поддерживается.

## Синтаксис

```
gophkeeper [глобальные опции] <команда> [опции] [аргументы]
```

Глобальные опции указываются **перед** именем команды; всё, что идёт после имени команды, относится к ней.

```
gophkeeper -a vault.example.com:50001 --cert ca.pem list      # верно
gophkeeper list -a vault.example.com:50001                    # неверно: -a не является опцией `list`
```

## Команды

| Команда | Назначение |
|---|---|
| [`register`](register.md) | Создать аккаунт и войти в него |
| [`login`](login.md) | Войти в существующий аккаунт |
| [`logout`](logout.md) | Удалить локальную сессию |
| [`add`](add.md) | Добавить секрет (`login`, `text`, `binary`, `card`) |
| [`list`](list.md) | Показать список секретов (имена, типы, id; без содержимого) |
| [`get`](get.md) | Показать один секрет |
| [`update`](update.md) | Изменить секрет в интерактивном режиме |
| [`delete`](delete.md) | Удалить секрет |
| [`version`](version.md) | Напечатать версию клиента |

`gophkeeper help` или `gophkeeper --help` печатает список команд и глобальных опций. `gophkeeper <команда> -h`
печатает опции конкретной команды.

## Глобальные опции

| Флаг | Переменная окружения | По умолчанию | Значение |
|---|---|---|---|
| `-a` | `ADDRESS` | `localhost:50001` | Адрес сервера, `host:port` |
| `-cert` | `CA_CERT` | *(пусто)* | Путь к PEM-файлу с сертификатом CA, которым подписан сертификат сервера |
| `-session` | `SESSION_FILE` | *(см. ниже)* | Путь к файлу сессии |
| `-l` | `LOG_LEVEL` | `info` | Уровень логирования: `debug`, `info`, `warn`, `error` |

**Приоритет.** значение по умолчанию < флаг < переменная окружения. Если заданы и флаг, и соответствующая
переменная окружения, **побеждает переменная окружения**.

Флаги в стиле Go принимают один или два дефиса (`-a` и `--a` — одно и то же).

### TLS

- `-cert` задан: соединение идёт по TLS, и доверие оказывается **только** CA из этого файла. Имя сервера
  берётся из `-a`, поэтому сертификат сервера должен содержать подходящий SAN (например, `localhost` или
  `127.0.0.1`).
- `-cert` не задан: соединение **без шифрования**, клиент пишет предупреждение в лог. Используйте это только
  для локальной разработки.
- Отсутствующий файл или файл без сертификатов — ошибка запуска. Молчаливого перехода на соединение без
  шифрования нет.

### Файл сессии

`login` и `register` записывают файл сессии, в котором лежат токен доступа и ключ шифрования. Расположение по
умолчанию: `gophkeeper/session.json` внутри пользовательского каталога конфигурации (`os.UserConfigDir`):

| ОС | Путь по умолчанию |
|---|---|
| Linux | `~/.config/gophkeeper/session.json` |
| macOS | `~/Library/Application Support/gophkeeper/session.json` |
| Windows | `%AppData%\gophkeeper\session.json` |

Относитесь к этому файлу как к незащищённому приватному SSH-ключу: любой, кто может его прочитать, сможет
прочитать ваши секреты, пока не истечёт токен. Файл привязан к адресу сервера, для которого создан;
использование с другим сервером завершается ошибкой `found credentials to another server, try login`.

Опция `-session` позволяет держать несколько независимых сессий (например, для разных серверов или
аккаунтов).

По умолчанию сессия действует 24 часа. Потом команды завершаются ошибкой `session expired, run login`;
выполните [`login`](login.md) заново.

## Пароли

Пароль никогда не передаётся флагом (он попал бы в историю оболочки). Команды, которым нужен пароль:

1. берут `GOPHKEEPER_PASSWORD`, если переменная задана и не пуста (для скриптов), иначе
2. запрашивают пароль без отображения вводимых символов.

Если ввод — не терминал (канал, файл), приглашения читают обычные строки из stdin.

## Потоки вывода

- Результаты команд идут в **stdout**.
- Приглашения к вводу, предупреждения и ошибки идут в **stderr**, поэтому перенаправление stdout их не
  захватывает.
- При запуске клиент всегда печатает в stdout две строки со сведениями о сборке (`Build version: …`,
  `Build date: …`), и записи лога тоже идут в stdout. Учитывайте это при разборе вывода в скриптах.

## Типы секретов

| Тип | Поля | Маскируется в `get` без `--show` |
|---|---|---|
| `login` | имя пользователя, пароль | пароль |
| `text` | одна строка текста | — |
| `binary` | имя файла и содержимое (из `--file`) | — |
| `card` | номер, владелец, срок действия, CVV | номер, CVV |

У каждого секрета есть **имя** и необязательные **метаданные** (пары `ключ=значение`, например адрес сайта
или заметка). Имя и метаданные тоже шифруются.

Ограничение: содержимое секрета не должно превышать 1 МиБ (см. [Ошибки](#ошибки)).

### Как указать секрет: `<id|name>`

`get`, `update` и `delete` принимают либо id секрета (UUID, который выводят `add` и `list`), либо его имя.
Если имя подходит нескольким секретам, команда завершается ошибкой и печатает подходящие id; повторите её с
id.

## Коды выхода

| Код | Значение |
|---|---|
| `0` | Успех (также `help` и `-h`) |
| `1` | Операция не удалась (сервер, сессия, не найдено, конфликт, …) |
| `2` | Ошибка использования: неверные аргументы, не указан флаг, некорректные данные, неизвестная команда, пустой ввод |
| `130` | Прервано по Ctrl+C / SIGTERM |

## Ошибки

Тексты сообщений программа выводит на английском.

| Сообщение | Что делать |
|---|---|
| `session expired, run login` | Токен истёк. Выполните `login`. |
| `unauthenticated, run login` | Нет файла сессии. Выполните `login` или `register`. |
| `found credentials to another server, try login` | Сессия относится к другому адресу сервера. Выполните `login` для этого сервера или укажите правильные `-a`/`-session`. |
| `login or password is incorrect, try again` | Неверные учётные данные. |
| `login is taken by another user, please try something else` | Выберите другой логин для `register`. |
| `record not found` | Нет секрета с таким id или именем. Проверьте через `list`. |
| `id or name X returned multiple values: [...]` | Используйте один из перечисленных id. |
| `record version is too old, please refresh` | Секрет тем временем изменили с другого клиента. Повторите команду, чтобы получить свежую версию. |
| `record size is bigger than limits, …` | Содержимое больше 1 МиБ. Сожмите или разделите его. |
| `invalid data provided` | Клиент или сервер отклонил введённые данные. |
| `internal error` | Непредвиденный сбой; запустите с `-l debug`, чтобы увидеть подробности. |

## Быстрый старт

```sh
# 1. Создайте аккаунт (пароль запрашивается дважды)
gophkeeper -a vault.example.com:50001 -cert ca.pem register --login alice

# 2. Сохраните секреты
gophkeeper -a vault.example.com:50001 -cert ca.pem add login --name github --meta url=github.com
gophkeeper -a vault.example.com:50001 -cert ca.pem add binary --name ssh-key --file ~/.ssh/id_ed25519

# 3. Прочитайте их
gophkeeper -a vault.example.com:50001 -cert ca.pem list
gophkeeper -a vault.example.com:50001 -cert ca.pem get --show github
```

Чтобы не повторять глобальные опции, задайте их один раз через окружение:

```sh
export ADDRESS=vault.example.com:50001
export CA_CERT=$HOME/ca.pem
gophkeeper list
```
