# Сертификаты (TLS)

Клиент и сервер общаются по gRPC. Без TLS токен доступа и производный ключ аутентификации идут по сети
открытым текстом (содержимое секретов при этом зашифровано в любом случае), поэтому для всего, кроме
локальной отладки, TLS нужен.

Нужны три вещи:

| Файл | Кому нужен | Что это |
|---|---|---|
| сертификат сервера | серверу (`-tls-cert`) | PEM, X.509 |
| приватный ключ сервера | серверу (`-tls-key`) | PEM |
| сертификат CA | клиенту (`-cert` / `CA_CERT`) | PEM; тот CA, которым подписан сертификат сервера |

## Вариант 1: свой CA через `certgen`

Утилита `cmd/certgen` создаёт учебный CA и подписанный им сертификат сервера.

```sh
make certs                                  # удалить старые файлы в certs/ и выпустить новые
go run ./cmd/certgen -o /путь/к/каталогу    # свой каталог
OUT_DIR=/путь/к/каталогу go run ./cmd/certgen
```

| Опция | Переменная окружения | По умолчанию | Значение |
|---|---|---|---|
| `-o` | `OUT_DIR` | текущий каталог | Каталог для файлов; создаётся при необходимости (права `0700`) |

Если заданы и флаг, и переменная, побеждает переменная окружения.

### Что создаётся

| Файл | Права | Назначение |
|---|---|---|
| `ca.pem` | `0644` | Сертификат CA. Передаётся клиентам (`-cert`) |
| `ca.key` | `0600` | Ключ CA. **Только для подписи; ни сервер, ни клиент его не используют.** Не копируйте |
| `server.pem` | `0644` | Сертификат сервера (`-tls-cert`) |
| `server.key` | `0600` | Ключ сервера (`-tls-key`) |

Ключи ECDSA P-256, формат PKCS#8. CA действует 10 лет, сертификат сервера — 1 год.

### Ограничения

- **`certgen` сам файлы не перезаписывает.** Если любой из четырёх уже существует, он завершается ошибкой
  (`error opening file …`). `make certs` обходит это: перед запуском он удаляет `ca.pem`, `ca.key`,
  `server.pem` и `server.key` в `certs/` (остальные файлы каталога не трогает). Новый запуск создаёт новый CA,
  поэтому клиентам нужно выдать новый `ca.pem`, а сервер перезапустить с новыми `server.pem`/`server.key`.
  При прямом вызове `go run ./cmd/certgen` удалите старые файлы сами или выберите другой каталог. Файлы, записанные до ошибки,
  остаются.
- **Адреса зашиты в код:** SAN сервера — `localhost`, `127.0.0.1` и `::1`. Задать другое имя или IP нельзя.
  Для сервера на другой машине используйте вариант 2.
- Каталог `certs/` указан в `.gitignore`; ключи в репозиторий не попадут.

### Подключение

```sh
bin/server --tls-cert certs/server.pem --tls-key certs/server.key
bin/client -a localhost:50001 -cert certs/ca.pem list
```

Адрес в `-a` должен быть одним из SAN сертификата. `localhost:50001` и `127.0.0.1:50001` подходят,
`my-laptop:50001` — нет: будет ошибка проверки сертификата.

## Вариант 2: сторонний сертификат

Подойдёт любой сертификат, удовлетворяющий требованиям ниже: от внутреннего корпоративного CA, от публичного
CA (например, Let's Encrypt) или созданный через `openssl`/`mkcert`.

### Требования к серверу

- Сертификат и ключ в **PEM**. Ключ может быть PKCS#8 (`BEGIN PRIVATE KEY`), PKCS#1 (`BEGIN RSA PRIVATE KEY`)
  или EC (`BEGIN EC PRIVATE KEY`). Зашифрованный паролем ключ не поддерживается.
- Ключ должен соответствовать сертификату.
- Если в файле сертификата несколько записей (цепочка), первой должна идти сертификат сервера, затем
  промежуточные.
- В сертификате должен быть **SAN**, совпадающий с адресом, который клиенты указывают в `-a`: DNS-имя или
  IP. Поле CN игнорируется.
- Расширение `extendedKeyUsage` должно разрешать `serverAuth` (или отсутствовать).
- Сервер принимает только **TLS 1.3**.
- Срок действия сертификата не истёк.

### Требования к клиенту

Клиент **не использует системное хранилище доверенных сертификатов**. Он строит пул только из PEM-файла,
указанного в `-cert`, и доверяет только ему. Поэтому:

- `-cert` должен указывать на сертификат CA (в PEM), которым подписан сертификат сервера, причём **даже для
  публичного CA**: для Let's Encrypt нужен его корневой или промежуточный сертификат в файле.
- В файле может быть несколько сертификатов подряд.
- Для самоподписанного сертификата сервера укажите в `-cert` сам этот сертификат.
- Без `-cert` клиент не запустится: режима без TLS нет.
- Файл без единого сертификата или отсутствующий файл — ошибка запуска клиента, а не переход на соединение без
  шифрования.

### Пример с `openssl` (сертификат для другого хоста)

```sh
# CA
openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:prime256v1 -nodes \
  -keyout ca.key -out ca.pem -days 3650 -subj "/O=My CA"

# ключ и запрос на сертификат сервера
openssl req -newkey ec -pkeyopt ec_paramgen_curve:prime256v1 -nodes \
  -keyout server.key -out server.csr -subj "/O=My Server"

# подпись с нужными SAN
openssl x509 -req -in server.csr -CA ca.pem -CAkey ca.key -CAcreateserial \
  -out server.pem -days 365 \
  -extfile <(printf "subjectAltName=DNS:vault.example.com,IP:192.0.2.10\nextendedKeyUsage=serverAuth")
```

Сервер запускается с `server.pem` и `server.key`, клиенты получают `ca.pem` и подключаются так:

```sh
bin/client -a vault.example.com:50001 -cert ca.pem list
```

## Частые ошибки

Любую проблему TLS на стороне клиента он показывает одинаково: `internal error` (даже с `-l debug` причина
не печатается). Диагностируйте по списку ниже.

| Симптом | Возможная причина |
|---|---|
| Сервер: `incomplete certificate config …` | Задан только один из `-tls-cert` / `-tls-key` |
| Сервер: `error loading certificate for gRPC …` | Файл не найден, не PEM, ключ не от этого сертификата или защищён паролем |
| Клиент: `internal error` при любой команде, обращающейся к серверу | Адрес в `-a` не входит в SAN сертификата |
| то же | В `-cert` не тот CA (или не тот сертификат для самоподписанного сервера) |
| то же | Сертификат сервера просрочен |
| Клиент: `CA certificate path is required` | Не задан `-cert` / `CA_CERT` |
| Сервер: `TLS certificate and key are required` | Не заданы `-tls-cert` / `-tls-key` |
| Клиент: `found credentials to another server, try login` | Файл сессии создан для другого адреса. `localhost:50001` и `127.0.0.1:50001` для него разные серверы |

Проверить сертификат сервера можно так:

```sh
openssl x509 -in server.pem -noout -subject -dates -ext subjectAltName
openssl verify -CAfile ca.pem server.pem
```
