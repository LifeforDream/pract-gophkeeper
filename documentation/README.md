# GophKeeper: руководство по использованию

GophKeeper — клиент-серверный менеджер паролей. Содержимое секретов (логины и пароли, текст, бинарные файлы,
данные банковских карт) шифруется на стороне клиента, сервер хранит его только как непрозрачный зашифрованный
блок.

## Быстрый старт

Нужен Go (версия указана в `go.mod`). Все команды выполняются из корня репозитория. В примере сервер хранит
данные в памяти и работает по TLS.

### 1. Сборка

```sh
make build
```

Появятся `bin/server` и `bin/client`. В документации по клиенту он называется `gophkeeper`; здесь для краткости
используется `bin/client`. Сборка под все платформы — `goreleaser check && goreleaser release --snapshot --clean` (файлы попадут в директорию dist/).
Также сборка автоматически выполняется в [Workflow Github](../.github/workflows/release.yml).

### 2. Сертификаты

```sh
make certs
```

В каталоге `certs/` появятся `ca.pem`, `ca.key`, `server.pem` и `server.key`. Подробности и работа со
сторонними сертификатами — в [certificates.md](certificates.md).

> `make certs` сначала удаляет эти четыре файла в `certs/`, так что повторный запуск выпускает новые CA и
> сертификат сервера. Сертификат старого CA перестанет подходить: раздайте клиентам новый `ca.pem`.

### 3. Запуск сервера

```sh
bin/server --tls-cert certs/server.pem --tls-key certs/server.key
```

Сервер слушает `localhost:50001`. Со встроенным хранилищем в памяти секреты `-s` (JWT) и `-f` (фейковая соль)
генерируются при каждом запуске случайно. **После перезапуска сервера все данные пропадают, а выданные токены
перестают действовать.** Для постоянного хранения используйте PostgreSQL, см. [server.md](server.md).

Остановка — Ctrl+C: сервер завершает текущие запросы (до 15 секунд) и выходит.

### 4. Работа с клиентом

В другом терминале. Укажите адрес и CA один раз через окружение, чтобы не повторять флаги:

```sh
export ADDRESS=localhost:50001
export CA_CERT=$PWD/certs/ca.pem

bin/client register --login alice          # пароль спросят дважды
bin/client add login --name github --meta url=github.com
bin/client add text --name note
bin/client list
bin/client get --show github
bin/client logout
```

Позже в новом сеансе: `bin/client login --login alice`.

> **Восстановления пароля нет.** Если забыть пароль, данные не расшифровать никому.

> Переменная `ADDRESS` читается и сервером, и клиентом. Если вы экспортировали её в той же оболочке, где
> запускаете сервер, сервер тоже начнёт слушать этот адрес. Для сервера в примере это совпадает с адресом
> по умолчанию.
